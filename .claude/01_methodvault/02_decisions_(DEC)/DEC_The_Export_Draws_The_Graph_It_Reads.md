## Context

Issue #99. The export has read the vault as a graph since
[[DEC_Reading_The_Vault_As_A_Graph]] (DEC-MTH-010), and it has never drawn
one. `traceability.html` is tables, `traceability_edges.csv` is an edge
list, and `traceability_index.md` carries one line per object and does not
show the REQ→TAE edge at all. [[DEC_Generated_Content_Is_Stored_Only_Where_CI_Proves_It]]
(DEC-MTH-037) put the export's real output at the top of `README.md`
deliberately as text, because there was nothing else to put there.

The entry that resulted is what the maintainer read back on 2026-08-09 and
rejected on two counts. Its first heading was "The output, before the
argument" — a sentence that only means something to a reader who already
knows what the output is and what the argument was. And its proof is a
wall of index lines, a record rather than a picture: the promise this
method makes is that a requirement reaches its evidence, and nothing on
the page drew that.

Both counts are one question here: what does the exporter emit so that a
reader with no prior context can see the loop, and how does that emission
stay provably current where it is stored.

## Options

- **A — Leave it as text and rewrite only the prose.** Rejected: it
  answers the readability half and not the visual half, and the visual
  half is the one #99 is about.
- **B — A PNG screenshot of `traceability.html`.** Rejected for the reason
  DEC-MTH-037 already rejected it: a binary carries no diff, so its
  currency is only checkable by re-rendering and comparing bytes, which
  makes the gate hostage to the browser on the runner.
- **C — Publish `traceability.html` through GitHub Pages.** Rejected: it
  stores no artifact, which is its merit, but it answers "beside the
  README" where #99 asks for "in it", and it needs a Pages decision this
  record is not.
- **D — Graphviz or another `.dot` renderer.** Rejected: GitHub renders
  neither natively, so the result is again an image somebody produces and
  nobody can diff.
- **E — A Mermaid node-link diagram, generated by the exporter from the
  same analysis that writes `traceability.json`, stored between marker
  comments in `README.md` under DEC-MTH-037's conditions (chosen).**

## Decision

The exporter gains a fifth format, `mermaid`, in its default set. It
writes `traceability_graph.mmd`: the diagram source and nothing else, no
Markdown fence, so the same bytes can be embedded in a fenced block and
compared against a fresh run by the CI step DEC-MTH-037 established.

**It draws no vault content it did not read.** Nodes and edges come from
`graph.nodes`, `graph.requirements` and `graph.edges` — the structures the
other four formats are written from. There is no second parse, and a
relation the graph does not carry cannot appear in the picture.

**It draws three of the eight declared relations, and says so.** Drawn are
`allocates`, `evidence` and `verifies`: the ones coverage is decided on.
All eight was built first and measured against the shipped worked example
— ten nodes, twenty edges and seven relation words above the fold, with
the requirements file standing unconnected beside three same-named
requirement rows, and the only closed cycles in the picture the accidental
`evidence`/`test-object` pairs rather than the chain the reader was meant
to follow. A picture that cannot be read fails the thing it was added for.

This is a narrowing, so it is named rather than assumed: in the diagram's
own header, which states the three kinds and points at
`traceability.json` and `traceability_edges.csv` for the rest, in
`vault_schema.json`, and here. That is the difference between a scope and
a silent loss — the export's rule is that nothing it can prove it lost is
lost without a word, not that every output carries everything.

**Node identity is synthetic and the vault's own identity is the label.**
A vault key is `ARC:ARC_Export` or `REQ_Battery_Monitoring (BAT)` — colons,
parentheses, spaces and non-ASCII, none of which Mermaid accepts as an id,
and `end`, `o` and `x` are reserved besides. Ids are therefore `o_`/`r_`
sanitisations of the key, disambiguated by a counter in sorted order. The
prefixes are not decoration: a requirements file may legally carry the id
of one of its own rows, and one namespace would silently merge the file
object with the requirement.

**Every label is escaped, because a label is a record.** `#`, `"`, `|`,
`<`, `>`, `&`, `{`, `}` and the backtick become Mermaid entity codes. An
allocation status is authored text and may contain any of them; a `|` alone
would close the edge label and take the whole diagram with it.

**Parallel edges are collapsed on `(kind, source, target, qualifier)`.** A
requirement allocated in several rows authors one `evidence` edge per row —
right in the JSON, four identical arrows in a picture.

**The output is machine-independent by construction.** No vault path, no
input digest, no generation time — so `traceability_graph.mmd` is
byte-identical with and without `--no-timestamp`, which is what lets the
tutorial quote it from a run that carries a timestamp.

**Three blocks are stored in `README.md`, each under DEC-MTH-037's four
conditions:** the diagram, the two count lines, and the index tail that
used to stand alone. "One movable block" becomes "one marker pair per
block"; the fourth condition is unchanged and applies three times, in one
parameterised CI step that also asserts every `traceability-*` marker pair
in the file is one it checks. A block nobody diffs is the failure this
widening could otherwise introduce.

## Justification

- The picture is generated from the vault by the same run that produces
  the numbers beside it, so the strongest visual on the page is also the
  one thing on it that cannot be stale without CI going red.
- The binding criterion was a reader with no prior context, and it decided
  the scope. Issue #99 states the goal as drawing the chain REQ→ARC→TAE;
  the complete graph draws that chain and four other things at the same
  size, and the four win the reader's attention.
- GitHub renders a ` ```mermaid ` fence natively, which is what makes a
  drawn graph diffable text rather than a binary — the property options B
  and D each give up.
- Synthetic ids and full label escaping are what make the format hold for
  a vault this repository does not own. The alternative, real keys as ids,
  works on the worked example and breaks on the first German vault.
- Refusing an unknown `--formats` value is folded in here rather than
  deferred: this record makes a CI step depend on a file that a mistyped
  format silently would not write, which is the hazard
  [[DEC_CI_Blocks_On_What_A_Session_Only_Warns_About]] (DEC-MTH-039)
  closed one flag over and recorded as an open residual.

## Consequences

- `export_traceability.py` gains `write_mermaid` and a sixth output file;
  `METHOD.md`, `SKILL.md`, `STRUCTURE.md`, `CONTRIBUTING.md`, the vault
  README and `vault_schema.json` each enumerate the artifacts and are
  corrected in the same pass.
- `--formats` is validated against the known set and refuses an unknown or
  empty value with exit 2, naming the valid values — closing issue #98.
  The accepted residual in DEC-MTH-039 that names this hazard as open is
  marked corrected by this record.
- `CONTRIBUTING.md`'s recipe is rewritten for three blocks; it is the only
  written instruction a contributor has for reproducing that check locally.
- `TUTORIAL.md` step 7 shows the reader their own graph, and the replay
  suite of [[DEC_A_Tutorial_Is_Replayed_Not_Reviewed]] (DEC-MTH-040)
  diffs it against the run.
- A large vault produces a diagram nobody can read, and Mermaid refuses a
  source over 50 000 characters. That limit is stated where the format is
  documented; the other four outputs are unaffected, and no gate depends
  on the picture being legible.
